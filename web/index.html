What it does

One proxy on the wire.

Every tool call an agent makes is a JSON-RPC message on a known transport. Sceau stands on that wire, whatever the agent is written in, and does four things with each message.

  • [deny]Block

    What the policy forbids never reaches the tool. A delete hidden behind a select is read for what it would do.

  • [hold]Wait

    Calls that are a person's decision stay open on the agent's side until someone seals or declines them.

  • [mask]Mask

    IBANs, cards, keys and addresses become tokens before the model reads them, and real values again on the way to a tool.

  • [sign]Record

    Each event is hashed onto the one before it and signed, so nobody can edit the past without it showing.

The policy

Rules you can read aloud.

Plain YAML, checked when Sceau starts: a rule it cannot read stops it from starting, it never falls through to allow. The first rule that matches decides, and an address that came out of your own CRM is told apart from one the agent made up.

- name: nothing is ever deleted
  match: crm/query
  if: [{ sql: [delete, drop, truncate] }]
  then: deny
- name: the agent reads the database freely
  match: crm/query
  if: [{ sql_only: [select] }]
  then: allow
- name: refunds above 200 EUR wait for finance
  match: payments/refund
  if: [{ arg: amount, gt: 200 }]
  then: hold
- name: bank details never leave by mail
  match: mail/send_email
  if: [{ carries: [iban, card] }]
  then: deny
  1. support-agentcrm/query select id, total_eur from ordersallowed
  2. support-agentpayments/refund { order: 88104, amount: 340 }held
  3. support-agentcrm/query select 1; delete from ordersblocked
  4. finance-copilotmail/send_email { to: accounts@supplier-billing… }blocked

Before the model reads it

The model gets a token. The tool gets the IBAN.

Results are scanned on their way back to the agent. IBANs are checked against their country's length and checksum, cards against Luhn, keys against the shapes the big providers use. Each value becomes a stable token; when the agent hands a token to a tool, Sceau puts the real value back. The table between the two lives in memory and is never written down.

And what it should never read

A supplier's invoice with a comment that says ignore previous instructions, white text in a PDF, Unicode tag characters that render as nothing: tool results that try to steer the model are withheld and recorded with what they said. Tool descriptions are fingerprinted too, so a server that rewrites a tool after you trusted it shows up in the ledger the moment it does.

Human in the loop

A hand on the seal.

A held call stays open on the agent's side while a person decides, in the console or in Slack. A click is too easy to give by mistake, so sealing is a press held for less than a second. Whoever seals, and when, goes into the record next to the call.

The black box

A record nobody quietly edits.

One JSON line per event, written to disk before the call goes on. Each line carries the SHA-256 of its content and of the line before it, and an Ed25519 signature. Change a number, drop an entry, reorder two, and every check after it fails, at the exact line. The hashes here are computed in your browser, now.

Run it

        
One container in front of your tools.

        
HTTP tool servers go behind /mcp/<name>. Local ones that speak over stdio are started through sceau wrap, which hands every message to the proxy and refuses calls if the proxy is gone. No account, no telemetry: the key and the ledger stay in one folder you own.
